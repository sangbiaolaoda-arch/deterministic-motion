# 设计契约

> 本文记录内核的设计判断，用于回答"为什么这样写"以及"改哪里会破坏确定性"。

## 1. 目标与非目标

**目标**：一个最小的、可复现的程序化动画内核，输入"帧号"，输出"画面"，跨机器一致。

**非目标**（本仓库不做）：SRT 解析、LLM 导演、MP4 编码封装、分布式渲染、可视化编辑器。

## 2. 不变量（每个机制都必须同时成立）

| 编号 | 不变量 | 破坏它的典型写法 |
| --- | --- | --- |
| I1 | `0 ≤ frame ≤ TOTAL_FRAMES-1` 且 `TOTAL_FRAMES = FPS×DURATION_S` | 把时长写成浮动值、允许越界帧 |
| I2 | `renderFrame(frame)` 是纯函数 | 在绘制里调用 `Date.now()` / `performance.now()`；按渲染顺序累加状态 |
| I3 | 随机来自带种子的 PRNG，种子=`hash(字符串)` | 直接 `Math.random()` |
| I4 | `local` 由 `(frame-startF)/durF` 推出，不单独存储 | 同时缓存一份"当前进度"字段 |
| I5 | `BEATS` 唯一真相；`startF/endF` 由累计时长派生，无缝拼满时间轴 | 手工维护每拍起止，导致重叠/空洞 |

## 3. 失败点清单（写实现前先预演）

- **边界**：首帧 `frame=0`、末帧 `frame=1349`、越界帧、拍与拍的交界帧。
- **回绕 / 取模**：无；时间线用线性扫描而非取模，避免负数取模陷阱。
- **输入合法性**：`frame` 传入浮点 / `NaN` / 负值 / 超大值。
- **状态一致性**：拍表与派生帧边界不同步；交叉溶解期同时引用"上一拍"与"当前拍"。
- **资源 / 随机**：未播种随机导致跨进程漂移（本项目历史上最贵的一类 bug）。
- **歧义**：最后一个采样帧是否"空白"；交叉溶解期是否漏画场景。

## 4. 关键决定（每条带理由）

1. **帧号是唯一时间来源**：`render(frame)` 而非 `render(now)`。这样预览、拖动、导出共享同一语义，消除"预览好看、导出错位"和"两次渲染不一致"两类问题。
2. **拍表是唯一真相**：只写每拍的**时长**，起止帧由累计时长派生（I5）。逻辑起点用 `round(t*FPS)` 断言校验，杜绝手工维护偏移。
3. **随机显式播种**：`mulberry32(hash('origin|dust'))`。种子来自稳定字符串而非运行期指针，跨进程/机器一致。缓存（`cached`）保证同一场景的随机元素只生成一次。
4. **交叉溶解用同一"帧"语义**：拍尾 15 帧内同时绘制上一拍（`p=1`）与当前拍（`p=local`），透明度用 `smoothstep` 过渡，时代色用 `lerpColor` 插值。全部是帧号的纯函数。
5. **环境能力优雅降级**：`ctx.letterSpacing` 不被支持时静默跳过；字体就绪后用 `document.fonts.ready` 重绘一帧（避免首帧缺字）。
6. **自检内置**：`window.__HH.selfTest()` 对采样帧渲染两次比较像素，把 I2 变成可运行的检查，而非口头承诺。

## 6. 反模式（改代码时避免）

- 在场景函数里读时间 / 随机 / 外部状态。
- 手工维护每拍 `startF`（应派生）。
- 为"看起来快"把随机结果缓存到模块外却不带种子。
- 让预览与"导出"走两套绘制代码。
